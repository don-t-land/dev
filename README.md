# 종이비행기 온라인

Three.js + WebSocket 멀티플레이 글라이더 게임.

## 실행

Node.js 22~24가 필요합니다.

```bash
npm ci
npm test
npm start          # → http://localhost:3000
```

준비 상태 확인은 `GET /healthz`에서 할 수 있으며, 응답에는 현재 배포 release ID가 포함됩니다.
브라우저 탭을 여러 개 열면 바로 멀티 테스트가 됩니다.
같은 네트워크의 다른 기기는 `http://<내IP>:3000` 으로 접속하세요.

## 게임 모드

- **멀리 날기 (DIST)** — 전원이 같은 시드로 생성된 7.5km 직선 협곡을 비행. 추락 시점의 직선 거리로 순위 결정. 금색 링은 속도 부스트. 라운드 150초.
- **오래 날기 (ARENA)** — 원형 아레나에서 Space로 종이 다트를 발사해 서로 격추. 최후 생존자 승리, 순위는 생존 시간. 링은 탄약 +1. 라운드 180초.

## 멀티플레이 방

- 로비에서 서버가 보내는 **공개 방 목록**을 확인하고 바로 참가할 수 있습니다.
- 모든 방은 혼동하기 어려운 문자로 구성된 고유 **6자리 초대 코드**를 가집니다.
- 비공개 방은 목록에 표시되지 않으며 초대 코드로만 참가할 수 있습니다.
- 대기실에는 참가자, 방장, 모드, 공개 여부와 인원이 실시간으로 표시됩니다.
- 라운드는 서버가 확인한 **방장만** 시작할 수 있습니다. 방장이 나가면 가장 먼저 참가한 조종사에게 권한이 이양됩니다.
- 진행 중 참가자는 다음 라운드까지 관전하며, 게임 화면의 리더보드는 서버가 계산·검증한 점수만 사용합니다.
- 결과 화면 뒤에는 자동 재시작하지 않고 대기실로 돌아가 방장이 다음 라운드를 시작합니다.

## 구조

```
server.js          # HTTP 정적 서빙 + WebSocket (방·세션·라운드·판정)
public/index.html  # 클라이언트 (로비 · 두 모드 · 렌더링 · 예측/보간)
```

- **세션**: 토큰을 localStorage에 저장, 재접속해도 이름·승수 유지 (서버 생존 동안)
- **맵 동기화**: 서버가 라운드마다 시드 하나만 보내고, 모든 클라이언트가 같은 시드로 같은 맵을 결정론적으로 생성
- **이동 동기화**: 자기 기체는 클라이언트 예측, 남의 기체는 15Hz 상태를 보간. 서버는 스폰 위치와 이동 예산으로 비정상 좌표 이동을 제한
- **격추 판정**: 서버가 최근 발사 궤적과 착탄 지점·대상 위치를 함께 검증하고 사용된 발사를 소모

## CI/CD

`main` push는 GitHub webhook으로 Jenkins Pipeline을 시작합니다. Jenkins는 테스트를 통과한 소스만 dontland의 immutable release 디렉터리에 준비하고, release별 health 응답을 확인한 뒤 `current` 심볼릭 링크를 원자적으로 전환합니다.

## 배포 시 주의

- HTTPS 뒤에 두면 클라이언트가 자동으로 `wss://`를 사용합니다
- 이동·점수·발사 궤적을 서버가 제한하지만 전체 물리는 여전히 클라이언트 예측 기반입니다. 경쟁 서비스 수준의 부정행위 방지가 필요하면 서버 권위 물리로 확장하세요
