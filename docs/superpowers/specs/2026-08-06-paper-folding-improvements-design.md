# 종이접기 개선 설계 (프로젝트 1/3)

작성일: 2026-08-06
상태: 사용자 승인 대기

## 배경과 로드맵

사용자 요청은 세 개의 독립 프로젝트로 분할되었고 아래 순서로 진행한다. 이 문서는 1번의 설계다.

1. **종이접기 개선** (이 문서) — 기본 비행기 프리셋, 실시간 비행 스탯, 접은 결과 3D 미리보기
2. **드롭인 멀티플레이** — 대기실·대기시간 제거. ARENA는 상시 진행 + 중도 참여(방 코드 유지 + 공용 세션 빠른참가), 격추 시 즉시 부활 또는 다시 접기 선택. 접기는 입장 시(시간제한 없음, 완료 즉시 시작). DIST는 라운드제 유지
3. **맵 랜덤 생성 개선** — 거리 기반 바이옴 밴드 + 시드 노이즈 지형, DIST에서 진행 거리에 따라 안개·하늘·장애물이 전환되는 연출. 기존 "시드 하나만 동기화" 아키텍처 유지

구현 완료 후 로컬 서버(`npm start`)를 띄워 사용자가 직접 확인한다.

## 목표

- 접기를 모르는/귀찮아하는 유저가 **원클릭으로 검증된 기본 비행기**를 얻고 바로 시작할 수 있다.
- 접을 때마다 **비행 특성 변화가 즉시 보여** 전략적인 접기가 가능하다.
- 2D 접기 결과가 **실제 3D 기체로 어떻게 보일지** 접기 화면에서 미리 확인할 수 있다.

## 비목표

- 접기 기하 모델(`paper-fold-model.js`)의 규칙 변경 — 기존 flat-fold 모델 그대로 사용
- 서버 검증 로직 변경 — 프리셋은 기존 커맨드 리플레이로 통과
- 접기 애니메이션, 대칭 접기 모드 (사용자가 선택하지 않음)

## A. 기본 비행기 프리셋

### 데이터

- 프리셋은 새 형식이 아니라 **기존 접기 커맨드 배열** `[{start, end, direction}, ...]`이다.
- 클래식 다트 접기 순서(코너 접기 2회 → 세로 반 접기 → 날개 접기 2회 수준, 5~7 커맨드)를 `[-1,1]²` 종이 좌표로 정의한다.
- 위치: `paper-fold-model.js`에 `PRESETS = { dart: [...] }` 와 `createPresetModel(name)`(내부적으로 `replayFoldCommands` 호출, 실패 시 `null`) 추가. 모델 파일은 서버(`server.js`)와 클라이언트가 공유하므로 양쪽에서 동일하게 접근 가능.

### UI 동작

- 접기 화면 컨트롤에 **"기본 비행기" 버튼** 추가 (`fold-controls` 영역).
- 클릭 시 현재 모델을 프리셋 리플레이 결과로 **교체**한다. 리플레이가 히스토리를 누적하므로 "한 번 펴기"로 프리셋 단계를 거꾸로 풀 수 있다.
- 프리셋 적용 후에도 남은 접기 횟수(10회 제한) 내에서 자유롭게 추가 접기 가능.
- 잠금(완성) 상태에서는 버튼 비활성.

### 품질 기준 (테스트로 강제)

- `replayFoldCommands(PRESETS.dart)`가 `null`이 아니어야 한다 (서버 검증 통과 보장).
- 산출 프로필: `liftScale ≥ 0.6`, `|rollBias| ≤ 0.05`, `stability ≥ 0.8` (클래식 다트다운 균형 잡힌 값, 구현 중 실측으로 임계값 미세조정 가능하나 "균형·비행 가능" 취지는 유지).

## B. 실시간 비행 스탯 패널

- 접기 화면에 스탯 패널 추가. 표시 항목: **양력(liftScale), 항력(dragScale), 안정성(stability), 실속속도(stallSpeed), 좌우균형(rollBias)**.
- 모델이 바뀔 때마다(접기·펴기·프리셋) `PaperAeroProfile.deriveAerodynamicProfile(model)`을 호출해 갱신.
- 각 항목은 게이지 바 + 수치로 표시하고, 직전 상태 대비 증감(▲/▼)을 함께 보여준다.
- `paper-aero-profile.js`가 접기 화면에서 로드되어 있어야 한다 (index.html 스크립트 순서 확인).
- 구현 위치: `paper-fold-ui.js` (스탯 계산·DOM 갱신은 순수 로직이므로 여기 유지).

## C. 접은 결과 3D 미리보기

- 접기 화면 한쪽에 작은 3D 뷰포트(별도 `<canvas>`)를 추가. 접힌 기체를 천천히 자동 회전시켜 보여준다.
- 렌더는 게임 내 기체와 **동일한 빌더** `makeFoldedCraftVisual`(index.html 모듈 스코프)를 재사용한다 — 미리보기와 실제 기체의 일치 보장.
- 결합 방식: `paperFoldingStage`에 `onModelChange(model)` 콜백 등록 API를 추가한다. index.html 모듈이 이 콜백을 구독해 미리보기 씬을 갱신한다. `paper-fold-ui.js`는 Three.js에 의존하지 않는다.
- 접지 않은 상태(커맨드 0개)에서는 평평한 종이 한 장을 표시한다.
- 미리보기 렌더러는 접기 화면이 활성일 때만 rAF 루프를 돌리고, 화면 이탈 시 정지·리소스 해제한다.

## D. 테스트

`node --test` 기반, 기존 `test/paper-fold-model.test.js`·`test/paper-aero-profile.test.js` 패턴을 따른다.

- 프리셋 리플레이가 유효 모델을 반환한다 (A 품질 기준 수치 포함).
- 프리셋 적용 후 `undoFold`가 단계별로 되돌린다.
- 프리셋 커맨드 직렬화가 4096자 제한과 10회 접기 제한 안에 있다.
- `onModelChange` 콜백이 접기·펴기·프리셋 시점에 호출된다 (paper-fold-ui는 DOM 의존이라 콜백 계약은 최소한으로 검증하거나 수동 확인).

## 데이터 흐름 (변경 없음 확인)

프리셋도 일반 접기와 동일하게 `fold_done` 메시지의 `commands` 문자열로 서버에 전송되고, 서버는 기존 `replayFoldCommands` → `deriveAerodynamicProfile` 경로로 검증·산출한다. 서버 변경 없음.

## 에러 처리

- 프리셋 리플레이 실패(이론상 발생 불가, 테스트로 방지) 시 현재 모델 유지 + 상태 메시지 표시.
- WebGL 컨텍스트 확보 실패 시 3D 미리보기만 숨기고 접기 기능은 정상 동작.
