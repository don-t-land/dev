# 3D 자유각도 종이접기 설계 (프로젝트 3/4)

작성일: 2026-08-06
상태: 사용자 승인 완료

## 배경 (사용자 확정 사항)

- 선을 그으면 선 기준으로 종이 면 영역이 나뉘고, 나뉜 영역을 드래그로 **원하는 각도만큼** 접을 수 있다.
- 접기는 **3D로 표시**하며 객체를 회전시키면서 접는다.
- 기존 2D 접기 화면을 **완전 대체**한다. 기존 다트 프리셋은 180° 접기로 이식한다.
- 면 관통(물리적으로 불가능한 겹침)은 **허용(무시)** — Origami Simulator와 동일한 게임적 단순화.
- 이후 프로젝트 4로 맵 생성(바이옴 밴드 + 노이즈)이 이어진다. 로컬 전용(원격 push·배포 금지).

## 목표

접는 각도가 자유로워져 상반각·수직 안정판 같은 실제 비행기 형상을 만들 수 있고, 그 형상이 비행 특성에 그대로 반영된다. 편집 화면 = 게임 내 기체 = 물리 충돌체가 동일한 3D 형상.

## 비목표

- 관통 방지·자기충돌 시뮬레이션
- 곡면 접기, 커브 접는선 (직선만)
- 서버 프로토콜 구조 변경 (`fold_done`/`fold_ok`/`spawned` 흐름 유지 — 커맨드 내용만 각도 포함으로 확장)

## 1. 접기 모델 (`paper-fold-model.js` 대체·확장)

### 자료 구조

- **전개도(material) 좌표계 유지**: 종이는 `[-1,1]²`, 면(faces)은 전개도를 분할하는 다각형. 전개도 좌표는 3D 상태와 무관하게 항상 겹침 없이 분할됨 — 커맨드 결정론의 근거.
- **커맨드**: `{ start:[x,y], end:[x,y], angle }` — start/end는 전개도 좌표의 접는선, angle은 라디안 `[-π, π]` (부호 = 방향, `|angle| ≥ 0.05` 미만이면 거부). 기존 `direction` 필드는 제거되고 angle 부호가 대체.
- **면**: `{ poly(전개도), folds: [foldIndex...] }` — 레이어 개념은 3D 배치로 대체되나, ±180° 근처 시각 겹침 방지용 미세 오프셋에 폴드 순서를 사용.
- **폴드**: `{ A(전개도 점), d(전개도 방향), angle, parents: [foldIndex...] }` — parents는 이 접는선 자신이 놓인 면의 folds (축의 3D 위치 계산에 필요).

### 접기 적용 규칙

1. 접는선 세그먼트의 중점이 속한 면을 찾고, 그 면이 속한 **강체 컴포넌트**(기존 접는선을 경계로 나뉘지 않고 인접한 면들의 연결 집합 — 전개도 기준, folds 집합이 동일한 면들의 연결 성분)를 구한다.
2. 접는선(무한 직선)이 그 컴포넌트의 면들만 분할한다 (`splitPolygon` 재사용). 분할 결과 양쪽 모두 최소 면적 이상이어야 하며, 아니면 커맨드 거부(현행과 동일한 "모델 원본 반환" 방식).
3. 진행 방향의 **왼쪽 영역**(현행 규칙 유지)의 면들에 새 foldIndex를 추가.
4. 되돌리기는 현행 히스토리 스냅샷 방식 유지.

### 3D 배치 계산 (`computeFoldedGeometry(model)` 신규)

- 전개도 점 `(x,y)` → 기저 3D `(x, 0, -y)` (현행 시각화와 동일한 매핑, 기수 = -z).
- 각 폴드 k의 3D 회전축: 전개도상의 직선 `A + t·d`를 폴드 k의 `parents` 회전들을 순서대로 적용해 3D로 보낸 것.
- 면의 정점 3D 위치: 면의 `folds`를 오름차순으로 돌며 각 폴드의 축·각도로 회전 누적.
- 반환: `{ faces: [{ vertices3: [[x,y,z]...], foldDepth }], bounds }` — 시각화·충돌체·프로필이 모두 이것을 소비.
- 순수 함수, 서버·클라이언트 공용 (Three.js 비의존 — 자체 벡터/쿼터니언 연산).

### 직렬화·검증

- `serializeFoldCommands`/`replayFoldCommands`는 angle 포함 형식으로 갱신 (4096자·MAX_FOLDS 10 유지, angle 유한성·범위 검증).
- 기존 형식(direction ±1)과의 호환은 불필요 (로컬 전용, 서버·클라이언트 동시 교체).

## 2. 공력 프로필 (`paper-aero-profile.js` 갱신)

`deriveAerodynamicProfile(model)`이 `computeFoldedGeometry` 결과를 사용:

- **planform**: 3D 정점의 XZ평면 투영 → convex hull → 면적·span(x폭)·chord(z깊이)·종횡비 (기존 공식 유지).
- **physicalArea**: 전개도 면적 합 (불변).
- **질량중심**: 3D 면적 가중 중심. rollBias = x편차, pitchBias = z편차 (기존 정규화 공식 유지).
- **상반각(dihedral) 항 신규**: 좌우 절반의 평균 y기울기 → 양(윗반각)이면 stability 가산, 음(아랫반각)이면 감산. `stability = clamp(기존식 + 0.35·dihedralFactor, .2, 1.4)`.
- 출력 필드 집합은 기존과 동일 + `dihedral` (Rapier 물리 `REQUIRED_PROFILE_FIELDS`가 기존 필드를 요구하므로 필드 제거 금지).

## 3. 3D 편집 UI (접기 화면 대체)

- `#fold-paper-canvas`는 Three.js WebGL 캔버스가 된다. 별도 3D 미리보기 패널(`#fold-preview-canvas`)은 제거 (편집 자체가 3D).
- 종이 렌더: `computeFoldedGeometry` 기반 양면 메시, 면별 미세 색 변화(현행 감성 유지), ±180° 겹침 방지용 폴드 순서 기반 미세 오프셋.
- **조작**:
  - 빈 공간 드래그 = 궤도 회전(orbit), 휠 = 줌.
  - 종이 표면 pointerdown→드래그→up = 접는선 긋기 (레이캐스트로 시작·끝점을 전개도 좌표로 역매핑, 시작점이 속한 강체 컴포넌트의 평면에 투영).
  - 선 확정 직후 **각도 조절 모드**: 위/아래 드래그로 -180°~+180° 실시간 미리보기(임시 angle로 geometry 재계산), 놓으면 커맨드 확정. ESC 또는 종이 밖 클릭으로 취소.
  - 조절 중 현재 각도를 도(°) 단위로 표시.
- **유지되는 UI**: 기본 비행기 프리셋(180° 커맨드로 이식), 실시간 스탯 패널, 한 번 펴기, 로비로 나가기, 비행기 완성, DIST용 타이머(timed 모드), live용 방 인원 표시.
- **제거되는 UI**: 골접기/산접기 토글(각도 부호가 대체), `#fold-preview-canvas`와 그 렌더러, `onModelChange` 3D 미리보기 구독(편집 뷰가 직접 대체).
- 골접기/산접기 버튼 제거로 생기는 `fold-direction` 영역에는 조작 안내(`돌리기: 빈 공간 드래그 · 접기: 종이에 선 긋고 위아래 드래그`)를 배치.

## 4. 게임 통합

- `makeFoldedCraftVisual`: `computeFoldedGeometry` 기반으로 재작성 (전 기체 공용 — 홈 마스코트·원격 기체·내 기체).
- `flight-physics-rapier.mjs`의 `makeColliderVertices`: 접힌 3D 정점을 그대로 사용하도록 갱신 (현재 구현이 모델을 어떻게 소비하는지 확인 후 동일 인터페이스 유지).
- 서버는 코드 변경 없음 (공유 모듈의 리플레이·프로필 함수 시그니처 불변).

## 5. 테스트

- 접기 수학: 90° 한 번 접기의 3D 정점 위치 수치 검증, 순차 접기 축 누적(부모 회전 적용) 검증, 강체 컴포넌트 분할(기존 접는선 넘어가는 선은 해당 컴포넌트만 분할), 거부 사례(너무 짧은 선·각도 0·범위 초과·MAX_FOLDS).
- 프리셋: dart 180° 이식 리플레이 통과 + 프로필 품질 기준(기존 임계값 유지) + rollBias 0.
- 프로필: 평평한 종이 대비 상반각 접기 시 stability 증가, 비대칭 접기 시 rollBias 발생.
- 직렬화: angle 포함 왕복, 4096자 한도.
- 서버 리플레이: 기존 arena-live 테스트의 fold_done 경로가 새 커맨드 형식으로 통과.
- UI·조작은 브라우저 검증.

## 에러 처리

- 유효하지 않은 커맨드(각도 범위·NaN·짧은 선·컴포넌트 분할 실패)는 현행처럼 원본 모델 반환, UI는 상태 문구로 안내.
- WebGL 컨텍스트 실패 시 접기 화면에 안내 문구 표시(접기 불가 — 기본 비행기 프리셋 버튼만 동작해 최소한 참여는 가능하게).
